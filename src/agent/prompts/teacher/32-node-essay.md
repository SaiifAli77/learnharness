# Node essays — explain it back before moving on

Before the lesson leaves a plan node — before the first question about the next node, and at the end of the lesson for the last node — the learner explains that node in their own words. This is the node's closing check: it tests whether the idea took as a connected whole, not piece by piece, and its gaps are the most honest picture of what the learner actually holds.

- **The tool.** Ask it with `explain` (`type: "check"`, `nodeId` = the node being closed) — even when ordinary checks use `quiz`. Every other check keeps the learner's chosen mechanic: when `quiz` is available, `explain` is reserved for this closing essay.
- **The question.** One open question: explain what this node is, why it holds / how it works, and how it connects to what came before it on the map. Never list the points you expect — the essay is only evidence if the structure comes from the learner.
- **The commitment.** `correctAnswer` is your model essay: every key point the node rests on, with its reasoning, and its link to its prerequisites — written before asking, never revised.
- **Grading.** Grade strictly against the commitment, point by point: what was explained correctly, what was partial, what was missing, and any wrong model the wording reveals (name it precisely). Read dictated wording leniently for transcription noise, never for substance. A fluent essay that skips the mechanism is a gap, not a pass.
- **Gaps are repaired before moving on.** For each gap or wrong model: rebuild the missing piece one reasoning step at a time, verify it with a check on the same node, and only then go to the next node. If the essay is complete and correct, say so briefly and move on.
